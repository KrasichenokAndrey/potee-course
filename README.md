# Курс ПОТЭЭ

Статический учебный сайт на Astro для самостоятельного изучения Правил по охране труда при эксплуатации электроустановок.

Сайт устроен как курс: раздел или приложение открывается отдельной страницей, внутри есть материал, презентация и проверочный тест. Результаты тестов и отметка об изучении сохраняются локально в браузере через `localStorage`.

Тест проходится по одной карточке. Нажатие на вариант сразу проверяет и фиксирует
ответ, показывает пояснение и пункт Правил, если они есть. При ошибке виден также
правильный ответ. Кнопка «Следующий вопрос» позволяет продолжить после чтения
пояснения; на последней карточке она меняется на «Показать результат».
Текущая карточка и ответы сохраняются при перезагрузке страницы. Итог записывается
после завершения теста; «Начать заново» сбрасывает текущую попытку, сохраняя предыдущий
итог до завершения новой. Завершенный тест можно пройти ещё раз.

## Структура

```text
source/
  rules/                 # исходные txt-файлы разделов и приложений
  presentations/         # исходные Markdown-презентации, если нужно хранить отдельно
  tests/                 # рабочие копии Markdown-тестов и manifest.json
src/
  content/
    modules/
      01-obschie-polozheniya/
        module.md
        presentation.md
        quiz.yaml
  components/
  layouts/
  pages/
scripts/
  generate-content.mjs
  import-tests.mjs
  validate-content.mjs
.github/
  workflows/
    deploy.yml
```

## Как запустить локально

```bash
npm install
npm run dev
```

Проверка перед публикацией:

```bash
npm run validate:content
npm run build
```

## Как добавить новый раздел

1. Положите исходный `.txt` в `source/rules/`.
2. Назовите файл по существующему шаблону: `III. НАЗВАНИЕ.txt` или `Приложение 9 НАЗВАНИЕ.txt`.
3. Запустите генерацию:

```bash
npm run generate:content
```

Генератор создаст папку в `src/content/modules/` и добавит `module.md`, `presentation.md`, `quiz.yaml`.

## Как добавить презентацию из NotebookLM

Откройте папку нужного модуля в `src/content/modules/` и замените содержимое `presentation.md`, оставив frontmatter сверху:

```markdown
---
title: "Презентация: I. ОБЩИЕ ПОЛОЖЕНИЯ"
moduleSlug: "01-obschie-polozheniya"
draft: false
---

# I. ОБЩИЕ ПОЛОЖЕНИЯ

## Слайд 1. Название

Текст слайда.
```

Презентация автоматически делится на слайды по заголовкам второго уровня `##`. Таблицы, списки и обычный Markdown поддерживаются.

## Как добавить тест

Файл теста находится рядом с материалом: `src/content/modules/<slug>/quiz.yaml`.

`answer` указывается как номер правильного варианта, начиная с `1`.

```yaml
title: "Проверка по разделу I"
moduleSlug: "01-obschie-polozheniya"
draft: false
questions:
  - type: single
    text: "Вопрос"
    options:
      - "Вариант 1"
      - "Вариант 2"
      - "Вариант 3"
    answer: 1
    explanation: "Почему этот ответ правильный"
    source: "Пункт 1.1"
```

Для готовых тестов поставьте `draft: false`. Для заготовок оставляйте `draft: true`.

### Импорт новых тестов

Оригиналы в `Исходники/Тесты` читаются без изменений. Чтобы скопировать их в
`source/tests/` и импортировать YAML-блоки в соответствующие модули:

```bash
npm run import:tests -- --copy-from-originals
```

Повторный импорт из рабочих копий (оригиналы для него не требуются):

```bash
npm run import:tests
npm run validate:content
npm run test:import
npm run build
```

Поддерживается один блок `yaml`/`yml` в каждом Markdown-файле. Имя файла должно
содержать номер: `III. НАЗВАНИЕ.md` или `Приложение 9 НАЗВАНИЕ.md`.
Сопоставление выполняется по `kind` и `number` из `module.md`, затем проверяется
точное совпадение `moduleSlug`. Неоднозначные, несопоставленные и дублирующие
файлы останавливают импорт до записи. Тесты модулей без нового файла сохраняются.

Рабочие копии и `source/tests/manifest.json` включены в версионируемые файлы проекта.
Манифест содержит полное сопоставление имен файлов с модулями, количество вопросов
и SHA-256 исходников. Полное имя оригинала хранится в `originalFile`, имя рабочей
копии — в `file`. Если имя превышает лимит Linux в 255 байт UTF-8, копия получает
короткое имя вида `XLII. tests.md`; оригинал сохраняет полное имя. Это необходимо
для checkout и сборки в GitHub Actions. Валидация проверяет структуру вопросов, диапазон `answer`,
полноту манифеста и точное соответствие YAML рабочим копиям; при наличии оригиналов
проверяет также их соответствие копиям. `npm run build` сначала запускает эту валидацию.

Пояснения `explanation` и ссылки `source` необязательны: при их отсутствии ничего
не добавляется. Сейчас все импортированные вопросы используют `type: single`;
множественный выбор останавливает импорт с ошибкой о неподдерживаемом типе.
`generate:content` сохраняет существующие `quiz.yaml`, поэтому не заменяет готовые
тесты шаблонами. Для обновления тестов используйте `import:tests`.

Новый банк содержит 47 тестов разделов I–XLVII, всего 1 656 вопросов.
Для приложений 1–8 новых тестов нет, их прежние шаблоны сохранены.
Результаты нового банка записываются в `potee:quiz-results:v2`: прежние попытки
остаются в браузере в `v1` и не отображаются как прохождение новых вопросов.
Отметки об изучении материалов сохраняются.

## GitHub Pages

В `astro.config.mjs` сейчас стоят безопасные placeholders:

```js
const githubUsername = "github-username";
const repoName = process.env.GITHUB_REPOSITORY?.split("/")[1] ?? "repo-name";
```

Перед публикацией замените `github-username` на ваш GitHub username. Имя репозитория GitHub Actions подставит автоматически из `GITHUB_REPOSITORY`; fallback `repo-name` нужен только для ручной локальной проверки Pages-base.

В настройках репозитория GitHub откройте `Settings -> Pages` и выберите источник публикации `GitHub Actions`.

После push в ветку `main` workflow `.github/workflows/deploy.yml` выполнит:

```bash
npm install
npm run validate:content
npm run build
```

Затем содержимое `dist/` будет опубликовано на GitHub Pages.
